Why These Algorithms Matter

Sorting and searching are the backbone of computer science. From databases to search engines, from social feeds to file systems — these algorithms are everywhere. Understanding them helps you write faster code and reason about performance.

Quick Rule of Thumb: For small data (<20 items), simple sorts are fine. For large data, always reach for O(n log n) algorithms. For searching a sorted list, Binary Search beats everything.

SIMPLE SORTS (O(n²))

Bubble, Selection, and Insertion sort are easy to understand and implement. They work great for small datasets or nearly-sorted data, but slow down badly on large inputs.

EFFICIENT SORTS (O(n log n))

Merge Sort and Quick Sort use divide-and-conquer strategy. They're significantly faster for large datasets. Python's built-in sorted() uses Timsort, a hybrid of Merge + Insertion Sort.

Bubble Sort
// The classic beginner algorithm — simple but slow
🫧 Bubble Sort
Best: O(n)
Avg: O(n²)
Space: O(1)

How it works

  • 1Start at the beginning of the list
  • 2Compare adjacent pairs of elements
  • 3If left > right, swap them
  • 4After each pass, the largest unsorted element "bubbles" to the end
  • 5Repeat for remaining unsorted portion
  • 6Stop early if no swaps occurred (already sorted)

Python Implementation

def bubble_sort(arr):
    n = len(arr)
    for i in range(n):
        swapped = False
        for j in range(0, n-i-1):
            if arr[j] > arr[j+1]:
                # Swap adjacent elements
                arr[j], arr[j+1] = arr[j+1], arr[j]
                swapped = True
        if not swapped:
            break  # Already sorted!
    return arr

# Example
arr = [5, 3, 8, 1, 9, 2]
print(bubble_sort(arr))
# Output: [1, 2, 3, 5, 8, 9]

When to use

✅ Use when:
• Learning/teaching sorting concepts
• Very small lists (< 10 items)
• Data is nearly sorted (O(n) best case)

❌ Avoid when:
• Large datasets — it's extremely slow
• Performance matters at all

Real world: Almost never used in production. Python's sorted() is always better.
Key insight: After pass 1, the largest element is in position. After pass 2, the 2nd largest is set. Each pass "bubbles" one more element into its final sorted position.
Selection Sort
// Find the minimum, place it — repeat
🎯 Selection Sort
Best: O(n²)
Avg: O(n²)
Space: O(1)

How it works

  • 1Divide list into sorted (left) and unsorted (right) parts
  • 2Scan the entire unsorted portion
  • 3Find the minimum element
  • 4Swap it with the first unsorted element
  • 5The sorted boundary moves one step right
  • 6Repeat until all elements are sorted

Press play to animate

Python Implementation

def selection_sort(arr):
    n = len(arr)
    for i in range(n):
        # Find min in unsorted portion
        min_idx = i
        for j in range(i+1, n):
            if arr[j] < arr[min_idx]:
                min_idx = j

        # Swap minimum into position
        arr[i], arr[min_idx] = arr[min_idx], arr[i]

    return arr

# Example
arr = [64, 25, 12, 22, 11]
print(selection_sort(arr))
# Output: [11, 12, 22, 25, 64]

When to use

✅ Use when:
• Memory writes are expensive (only n swaps!)
• Small datasets where simplicity matters
• You need exactly n-1 swaps guaranteed

❌ Avoid when:
• Large data — always O(n²) with no best case
• Data might already be sorted (no optimization)

Advantage over Bubble: Makes at most O(n) swaps (Bubble can make O(n²) swaps).
Key insight: Selection sort always does exactly n(n-1)/2 comparisons regardless of input, but only n-1 swaps. It's predictable but not adaptive — it can't take advantage of an already-sorted list.
Insertion Sort
// Like sorting playing cards in your hand
🃏 Insertion Sort
Best: O(n)
Avg: O(n²)
Space: O(1)

How it works

  • 1Start with the 2nd element (1st is "sorted")
  • 2Pick the current element as the "key"
  • 3Compare key with elements to its left
  • 4Shift larger elements one position right
  • 5Insert key into its correct position
  • 6Move to next element and repeat

Step-by-step: [5, 2, 4, 6, 1, 3]

Start: [5] | 2, 4, 6, 1, 3
Pass 1: [2, 5] | 4, 6, 1, 3
Pass 2: [2, 4, 5] | 6, 1, 3
Pass 3: [2, 4, 5, 6] | 1, 3
Pass 4: [1, 2, 4, 5, 6] | 3
Done: [1, 2, 3, 4, 5, 6] ✓

Python Implementation

def insertion_sort(arr):
    for i in range(1, len(arr)):
        key = arr[i]  # Element to insert
        j = i - 1

        # Shift larger elements right
        while j >= 0 and arr[j] > key:
            arr[j + 1] = arr[j]
            j -= 1

        # Place key in correct spot
        arr[j + 1] = key

    return arr

# Example
arr = [5, 2, 4, 6, 1, 3]
print(insertion_sort(arr))
# Output: [1, 2, 3, 4, 5, 6]

When to use

✅ Use when:
• Data is nearly sorted (very fast!)
• Small lists or streaming data
• You need a stable sort with O(1) space
• Online sorting (process items as they arrive)

❌ Avoid when:
• Large, randomly ordered datasets

Fun fact: Python's Timsort uses Insertion Sort for small subarrays — it's that good for small data!
Key insight: Think of how you sort cards — you pick one up, slide it into its correct position among already-sorted cards. That's exactly what Insertion Sort does. It's the best simple sort for nearly-sorted data.
Merge Sort
// Divide and conquer — split, sort, merge
⚡ Merge Sort
All cases: O(n log n)
Space: O(n)
Stable ✓

[38, 27, 43]      [3, 9, 82, 10]
↙↘              ↙↘
[38] [27,43]    [3,9] [82,10]
⬆ merge sorted ⬆
[27, 38, 43]    [3, 9, 10, 82]
⬆ merge sorted ⬆
[3, 9, 10, 27, 38, 43, 82] ✓

How it works

  • 1Divide: Split the list in half recursively until each piece has 1 element
  • 2A single element is already sorted by definition
  • 3Merge: Compare the fronts of two sorted halves
  • 4Take the smaller element and add to result
  • 5Repeat until both halves are exhausted
  • 6Bubble up — the merged results feed into larger merges

Python Implementation

def merge_sort(arr):
    if len(arr) <= 1:
        return arr  # Base case

    mid = len(arr) // 2
    left = merge_sort(arr[:mid])
    right = merge_sort(arr[mid:])

    return merge(left, right)

def merge(left, right):
    result = []
    i = j = 0

    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            result.append(left[i]); i += 1
        else:
            result.append(right[j]); j += 1

    result += left[i:] + right[j:]
    return result

# Output: [3, 9, 10, 27, 38, 43, 82]

When to use

✅ Use when: You need guaranteed O(n log n) performance · Sorting linked lists (great for this!) · You need a stable sort · External sorting (data doesn't fit in memory — merge sorted chunks from disk)

❌ Avoid when: Memory is critical (needs O(n) extra space) · Very small lists (overhead isn't worth it)

Stability means: Equal elements maintain their original order — crucial when sorting objects by multiple fields.
Why O(n log n)? Splitting takes O(log n) levels of recursion. At each level, merging takes O(n) total work. So: log n levels × n work = O(n log n).
Quick Sort
// The fastest sort in practice — pivot and partition
🚀 Quick Sort
Avg: O(n log n)
Worst: O(n²)
Space: O(log n)

Partition step — pivot = 3, array = [3, 6, 8, 10, 1, 2, 1]

Initial: [3, 6, 8, 10, 1, 2, 1] ← pivot = 3
After: [1, 2, 1, 3, 6, 8, 10]
←smaller→ pivot ←larger→
Left: [1, 2, 1] → sort recursively
Right: [6, 8, 10] → sort recursively
Result: [1, 1, 2, 3, 6, 8, 10] ✓

How it works

  • 1Choose a pivot element (often last, first, or random)
  • 2Partition: move all elements smaller than pivot to its left
  • 3Move all elements larger than pivot to its right
  • 4The pivot is now in its final sorted position
  • 5Recursively apply to left and right sub-arrays
  • 6Base case: arrays of 0 or 1 element are sorted

Python Implementation

def quick_sort(arr):
    if len(arr) <= 1:
        return arr

    pivot = arr[len(arr) // 2]
    left  = [x for x in arr if x < pivot]
    mid   = [x for x in arr if x == pivot]
    right = [x for x in arr if x > pivot]

    return quick_sort(left) + mid + quick_sort(right)

# Example
arr = [3, 6, 8, 10, 1, 2, 1]
print(quick_sort(arr))
# Output: [1, 1, 2, 3, 6, 8, 10]

When to use

✅ Use when: General purpose sorting (fastest in practice due to cache efficiency) · In-place sorting needed · Average case performance matters more than worst case

❌ Avoid when: Input might be already sorted (can degrade to O(n²) with bad pivot choice) · Stability is required (not a stable sort) · Guaranteed worst-case needed → use Merge Sort

Fix worst case: Use random pivot selection to avoid O(n²) on sorted/reverse-sorted data.
Quick Sort vs Merge Sort: Quick Sort is typically faster in practice due to better cache performance and less memory use, but Merge Sort guarantees O(n log n) even in the worst case. When in doubt in an interview, mention both and explain the trade-off.
Searching Algorithms
// Finding needles in haystacks — two very different approaches
🔍 Linear Search
Best: O(1)
Worst: O(n)
Space: O(1)
Works on unsorted ✓

How it works

  • 1Start at the first element
  • 2Compare with the target value
  • 3If match found → return index
  • 4If not → move to next element
  • 5Repeat until found or end of list
  • 6If end reached → target not found
Array: [14, 33, 27, 10, 35, 19, 42]
Target: 27
Check 14 ✗ → 33 ✗ → 27 ✓ (index 2)

Python Implementation

def linear_search(arr, target):
    for i, val in enumerate(arr):
        if val == target:
            return i  # Found! Return index
    return -1  # Not found

# Example
arr = [14, 33, 27, 10, 35]
result = linear_search(arr, 27)
print(result)  # Output: 2

# Python's built-in equivalent:
arr.index(27)  # Same thing!
27 in arr      # True/False version
✅ Use when: List is unsorted · List is small · Searching once (sorting first would be slower) · Any data type
⚡ Binary Search
Best: O(1)
Worst: O(log n)
Space: O(1)
Requires sorted! ⚠

Interactive Demo — search for 23

How it works

  • 1List MUST be sorted first
  • 2Look at the middle element
  • 3If middle == target → found!
  • 4If target < middle → search LEFT half
  • 5If target > middle → search RIGHT half
  • 6Repeat — each step halves the search space
1 billion items → max 30 comparisons
log₂(1,000,000,000) ≈ 30 🤯

Python Implementation

def binary_search(arr, target):
    left, right = 0, len(arr) - 1

    while left <= right:
        mid = (left + right) // 2

        if arr[mid] == target:
            return mid   # Found!
        elif arr[mid] < target:
            left = mid + 1  # Go right
        else:
            right = mid - 1 # Go left

    return -1  # Not found

# Python's built-in (bisect module):
import bisect
bisect.bisect_left(arr, target)  # Same!
The magic of logarithms: Binary search eliminates HALF the remaining candidates with each comparison. For n=1024: just 10 steps. For n=1,048,576: just 20 steps. This is why O(log n) is so powerful — it barely grows as data explodes in size.
